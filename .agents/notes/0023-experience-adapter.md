# Experience adapter

The experience contract is additive in `packages/contracts/src/experience.ts`; its operation table drives OpenAPI and the scenario API. Generated client types include every operation. `docs/CLIENT.md` is the presentation guide. Existing record routes remain compatible.

Conversations use durable chat jobs and separate turns. Agent changes select the next turn; an active turn keeps its agent. Connection access is intersected at proposal, admission, and dispatch. A missing or foreign agent fails closed. The asks-before-acting preference adds review to reversible writes, while local drafts remain available without sending. Per-turn intent identity and spending preserve retries within a turn and separate later requests.

`ExperienceEvents` materializes safe projections on the existing event sequence. Raw records remain internal. Connector-specific projectors produce compound action labels, sources, cards, and receipts. Narration uses the zero-cost `say` path. An unconfirmed effect prevents a completed turn and a done trail step. Stop fences effects and preserves partial text; queued pause/resume reuses the same turn. Running pause returns typed unavailability unless the runtime provides safe checkpoints.

Explicit draft sends and undo create private command attempts linked to the originating conversation. Those attempts use the broker and never enter the runtime catalog. A send requires a complete review, including Cc/Bcc and the full body; unsafe or oversized previews cannot be approved. Standing rules require exact trusted destinations, count caps, expiry, and re-consent. Reservations count conservatively, and revocation is checked again at dispatch. Conditional calendar deletion is reversible; sending, draft discard without connector support, and file restoration without a prior version return typed unavailability.

Questions retain offered option ids through the owner queue. Saved details use the existing correction, dependency, suppression, and forget paths. Plans project milestones from child work or a person's done state. Agent milestones use durable scheduled wakes. Routines use existing schedule triggers and retain separate occurrence allowances. Profile, tasks, home, and lexical search are session-scoped; recent action and calendar search is bounded to 500 confirmed records.

Magic-link sign-in uses the configured owner's mailbox and public address. Only a digest is stored; links expire after ten minutes, bind the connection generation, and consume once under a database lock. The token reaches the browser as a fragment and the normal session cookie is created on consumption. Sign-in mail does not enter runtime-visible records. Google/Apple sign-in, sharing, browser controls, music, and live data are typed unavailable capabilities.

The scenario API uses the same schemas and pure projection functions. Its repair scenario prepares a draft before an explicit reviewed send, and its uncertain scenario preserves the unconfirmed outcome without repeating the send. Mock state is process-local.

Validation commands are `bun run typecheck`, `bun run lint`, `bun run test:plugin`, and the full `bun test --max-concurrency=2`, run with no other suite sharing the database. Focused experience integration tests cover authenticated space isolation, repeated submissions, quick choices, memory correction/forgetting, two routine occurrences, agent restrictions, complete send previews, bounded rules, revocation, undo, stop, and durable trail replay. `REPORT.md` records actual command results and remaining limitations.
